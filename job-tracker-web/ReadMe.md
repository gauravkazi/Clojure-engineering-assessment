### Job Tracker Web Dashboard Demo 3

A web-based job application tracking dashboard built with ClojureScript and Reagent. The application connects to a REST API built with Clojure and Ring to retrieve, create, and update job applications.

This project is Demo 3 of my Clojure Engineering Assessment, demonstrating how ClojureScript can be used to build an interactive web application that communicates with a backend API.

The dashboard also includes an AI-powered job matching feature that compares a job description against my skills using the Gemini API and stores the analysis results in PostgreSQL.

### Live Demo

* Frontend: https://clojure-engineering-assessment-job.vercel.app
* Backend API: https://job-tracker-api-qdpd.onrender.com
* Backend Applications Endpoint: https://job-tracker-api-qdpd.onrender.com/applications
* Frontend Hosting: Vercel
* Backend Hosting: Render

### Features

* View Applications: Fetch and display job applications from the backend API.
* Add Applications: Submit new job applications with company and job role information.
* Update Application Status: Change an application’s status using its unique application ID.
* Persistent Backend Updates: Save changes through the backend API so they can be retrieved after refreshing the page, subject to the backend’s storage configuration.
* Reactive UI: Automatically update the dashboard when application data changes.
* REST API Integration: Communicate with the backend using HTTP requests and JSON.
* Status Management: Track applications through statuses such as Applied, Interview, Offer, and Rejected.
* AI-Powered Job Matching: Analyze a job description against my predefined skills using the Gemini API.
* Match Score: Display an AI-generated score indicating how closely the job description matches my skills.
* Matching Skills: Identify skills from my profile that match the requirements in a job description.
* Missing Skills: Identify skills that appear to be missing from my profile based on the job description.
* AI Analysis Summary: Display a summary of the job match generated by the AI model.
* Latest Analysis Retrieval: Retrieve the latest saved AI analysis from the backend after refreshing the dashboard.
* PostgreSQL Persistence: Store AI analysis results, including the job description, match score, summary, matching skills, and missing skills.
* Production Deployment: Deploy the compiled frontend separately from the backend.

### Getting Started

Follow these steps to run the frontend locally.

Prerequisites

Install the following tools:

* Java JDK
* Clojure CLI
* Node.js and npm
* Git

The ClojureScript compiler uses the configured ClojureScript dependencies, while npm manages the frontend’s JavaScript tooling.

1. Clone the Repository

git clone https://github.com/gauravkazi/Clojure-engineering-assessment.git

2. Navigate to the Frontend Directory

cd Clojure-engineering-assessment/job-tracker-web

If you already cloned the repository and are inside its root directory, simply run:

cd job-tracker-web

3. Install Dependencies

npm install

4. Configure the Backend URL

Open:

src/app/core.cljs

Find the api-url definition.

For local backend development, use:

(def api-url
  (if (= "localhost" js/location.hostname)
    "http://localhost:3000"
    "https://job-tracker-api-qdpd.onrender.com"))

This configuration uses the local backend when the frontend is accessed through localhost and the deployed backend otherwise.

Choose the appropriate configuration if your development setup uses a different hostname or port.

5. Start the Development Environment

Ensure the backend API is running, then execute:

npx shadow-cljs watch app

Shadow CLJS compiles the application and watches for source changes.

Open the local development URL configured in shadow-cljs.edn:

http://localhost:8080

Keep the development process running while testing the application.

### Backend API Integration

The frontend communicates with the backend through REST API endpoints.

Fetch Applications

Method: GET

GET /applications

Retrieves the job applications stored by the backend.

Add an Application

Method: POST

POST /applications
Content-Type: application/json

Example request body:

{
  "company": "Example Company",
  "role": "Backend Developer"
}

The backend creates a new application and assigns it a unique ID.

Update Application Status

Method: PATCH

The backend supports updating an application using its unique ID.

The exact request URL and accepted request body must match the backend’s implemented route.

Example request body:

{
  "status": "interview"
}

Supported statuses:

* applied
* interview
* offer
* rejected

The exact status values must match those accepted by the backend API.

### AI Job Matching

The dashboard includes an AI-powered feature that compares a job description against a predefined collection of skills.

How to Use It

1. Open the Job Tracker dashboard.
2. Enter a job description in the AI matching section.
3. Submit the description for analysis.
4. The frontend sends the job description to the backend.
5. The backend processes the request using the Gemini API.
6. The returned analysis is displayed on the dashboard.

The analysis includes:

* A match score.
* Matching skills.
* Missing skills.
* An AI-generated summary.

The match score and skill analysis are generated by the AI model. They should be treated as estimates rather than a guaranteed assessment of suitability for a job.

### AI Matching API Endpoints

Submit a job description for analysis

Method: POST

POST /match
Content-Type: application/json

The request contains the job description.

Example request body:

{
  "description": "We are looking for a backend developer with Node.js, REST API, PostgreSQL, and Docker experience."
}

The backend validates the description, requests an analysis from Gemini, and saves a successful result in PostgreSQL.

The response contains the analysis result, including the match score, matching skills, missing skills, and summary.

Retrieve the latest analysis

Method: GET

GET /match/latest

This endpoint retrieves the latest saved AI analysis from PostgreSQL.

The frontend uses this endpoint to restore the latest result when the dashboard initializes, allowing the analysis to remain available after a page refresh.

If no saved analysis exists, the endpoint can return a 404 response.

### How It Works

The application follows a frontend–backend architecture.

1. The user opens the dashboard.
2. The ClojureScript application initializes the Reagent UI.
3. The frontend sends a GET request to retrieve applications.
4. The backend returns application data as JSON.
5. The frontend converts the JSON response into ClojureScript data structures and updates its reactive state.
6. When a user adds an application, the frontend sends a POST request.
7. When a user changes an application’s status, the frontend sends a request containing the application’s unique ID and the new status.
8. After a successful mutation, the frontend fetches the updated application list.
9. The dashboard displays the latest application data.
10. When the user submits a job description for AI matching, the frontend sends it to the backend’s /match endpoint.
11. The backend validates the input and sends a request to the Gemini API.
12. Gemini generates the matching result, which the backend returns to the frontend.
13. The backend saves the successful analysis result in PostgreSQL.
14. When the dashboard initializes, the frontend requests /match/latest to retrieve the most recent saved analysis.
15. The dashboard displays the retrieved analysis.

The backend is responsible for processing requests and managing data persistence. The frontend retrieves data from the API rather than relying solely on browser memory.

Application records and AI analysis results use different storage mechanisms in the current implementation: application records use the existing application storage, while AI analysis results are stored in PostgreSQL.

Framework Preset	Other

### Backend — Render

The frontend communicates with the deployed Clojure backend hosted on Render.

https://job-tracker-api-qdpd.onrender.com

### PostgreSQL — Render

The backend uses a Render PostgreSQL database to store AI analysis results.

The database connection is configured through the backend’s DATABASE_URL environment variable.

Database credentials are configured on the backend hosting platform rather than embedded in the frontend source code.

### CORS Configuration

Because the frontend and backend are hosted on different domains, the backend must allow requests from the deployed Vercel origin.

The backend’s allowed origins should include:

https://clojure-engineering-assessment-job.vercel.app

The allowed origin must match the actual frontend domain. If the domain changes, update the backend configuration accordingly.

### Notes and Limitations

* The frontend requires a reachable backend API to retrieve and modify applications.
* Cross-origin requests depend on the backend’s CORS configuration.
* Render deployments may experience cold starts, which can make the first request slower.
* Application storage and AI analysis storage are separate in the current implementation.
* AI matching depends on the availability of the Gemini API and a valid backend API key.
* The Gemini API key must remain on the backend and must not be exposed in frontend code.
* The AI-generated score and skill analysis may not perfectly reflect a recruiter’s evaluation.
* The production frontend must use the deployed backend URL rather than localhost.
* If the backend is configured to retrieve only the latest AI analysis, the dashboard restores that result rather than maintaining a separate analysis history.
